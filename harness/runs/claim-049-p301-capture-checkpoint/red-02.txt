THE ROOT CAUSE (the isolated probe — a single import, direct CLI):

  File "harness/commands.py", in _spine
      recorded_hash, recorded_ref = row.split("|")
  ValueError: not enough values to unpack (expected 2, got 1)

  The first implementation's _sess_row filter was
      next((l for l in lines if l and "MARK" not in l), "")
  — it accepted ANY non-empty non-marker line as a result row. psql prints
  COMMAND TAGS (SET / INSERT 0 1 / BEGIN / COMMIT) on stdout even in -A -t
  mode; the Session's own `SET app.current_owner=...` emitted "SET" as the
  first line of every read, so the replay check's two-column unpack crashed
  on every command. CAP-15 alone passed — the only case whose refusal path
  runs before any session read.

  THE FIX (commit B, same slice): every _sess_row read is now pipe-delimited
  (multi-column rows via `|| '|' ||`; scalars carry a trailing '|') and the
  filter is the record_event-proven form — `"|" in l and "MARK" not in l` —
  which command tags can never satisfy. The lesson re-learned: the '|' filter
  on the original replay check was never a formatting accident; it is the
  load-bearing separation of RESULT ROWS from psql's own chatter. A reader
  that would accept a command tag would accept a forged row.
