## §4 Findings

**F2-077-5 (P3, NEW, in-slice, OPEN) — `_agent_audit` interpolates the owner UNESCAPED into its SQL batch; a quote-bearing owner's agent read is served and then fails loudly with no audit row.**

- **Where:** `harness/query.py`, `_agent_audit` (≈ lines 1072–1075): `pg.psql(f"SET app.current_owner='{owner}'; INSERT INTO arv.agent_read_log (…) VALUES (gen_random_uuid(), {qid}, '{owner}', '{arm}', …)")`. The owner travels raw into BOTH the GUC set and the VALUES list — diverging from the file's own convention (`_read` escapes via `owner.replace("'", "''")`; commands.py's `_q` likewise). (`arm` is the parser's closed set and `qid`/`qaft`/`qlim` are quoted/int-coerced — the owner is the unescaped one.)
- **Reproduced live** (rig `arv_sev77r2b…`, fresh-migrated): minted a credential for owner `O'Brien`, imported a source, then `--agent-token list-library`: the read itself is served (stdout byte-equal to the owner's own read, which succeeds because `_read` escapes), then `FAIL ARV-AGT-005: … ERROR: syntax error at or near "Brien"` at the `SET app.current_owner='O'Brien'` line, exit 1, and **no audit row lands** (verified: 0 rows for the credential).
- **Impact, honestly bounded:** (a) the agent-read path is broken for the quote-bearing-owner class — the read content is printed and then the command exits 1, so the slice's "an unaudited agent read is a contract violation, never a silent pass" letter holds observably (fail-loud, no consumer can mistake it for success), but the served read is left unrecorded; (b) the unescaped interpolation is SQL-injection-shaped — but the injectable value is the owner's own scope, fixed at mint by the caller, and the rig's CLI already accepts a free-form `--owner` from any local caller (single-user trust model), so no privilege boundary is crossed. No cross-owner escalation, no data corruption, no crash class (the psql error is surfaced through the named ARV-AGT-005).
- **Severity rationale:** P3 — fail-loud, narrow trigger (owner_scope containing a single quote; the suite's owners are A/B), zero escalation, one-line repair. Round 1's 56 probes did not cover a quote-bearing owner (the AGT suite uses only `A`/`B`), which is exactly the gap this round's characterization rig probed.
- **Repair:** escape the owner in `_agent_audit` with the file's own convention (`owner.replace("'", "''")` — ideally via the same helper shape `_read` uses), plus one AGT pin for a quote-bearing owner so the class stays closed.
