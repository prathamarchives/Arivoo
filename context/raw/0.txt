2. Layer 0 — Lock the system contract before the schema
The architecture needs a small set of top-level laws that every future implementation must follow.

Ground truth is durable
User-authored content, source files, committed revisions, explicit references and provenance are the durable record. Model outputs do not overwrite them.
Interpretation is allowed to evolve
Embeddings, candidate sets, inferred edges, concept clusters and belief scores are derived data. They can be superseded and rebuilt under new versions without rewriting original evidence.
Capture never waits for intelligence
Save and acknowledge the user's work independently of embedding, retrieval and Kev. Failures in those later stages must not lose or corrupt the captured object.
Enrichment is autonomous
There is no recurring accept/reject queue. Automatic transitions use explicit policies, stored evidence, confidence criteria, circuit breakers and reversible state changes.
Every derived result is explainable and reproducible
A model-generated relationship identifies the evidence, revisions, candidate-generation path, model version and policy that produced it.
Agents are clients of Arivo
AIOS and future agents use controlled APIs. They do not receive unrestricted access to the database or permission to overwrite the underlying evidence.
One qualification matters. “Nothing disappears” should mean that work is never lost or silently erased, and that the system preserves history and supports recovery. An explicit purge request is a separate operation that must actually erase the specified data under a defined retention policy.

These laws become acceptance criteria. A change that violates one needs an explicit architectural decision, not an implementation agent's assumption.

Immediate specification changes
The new autonomy design needs to replace these older rules:

Rung-based progression requiring judged suggestions and recurring audits.

Interactive semantic decisions that require your acceptance before creating any edge.

Manual confirmation for alias creation and concept promotion.

Permanent prohibition on automatic merges.

The rule that no inferred edges can ever contribute to further candidate discovery.

The older autonomy ladder and graph policy are defined in the existing file, so this is a deliberate change to the specification, not a detail for agents to infer.

3. Layer 1 — Domain model and identity
Locked direction: distinguish the identity of the thing, its content, its origin and its relationships.

For Arivo, these are different concepts:

A source work represents the intellectual work.

An edition or source version represents a particular version of that work.

An imported asset represents the particular file and its bytes.

A passage is generated from a source version and a chunking recipe.

A highlight, note or journal block represents material you created or deliberately preserved.

A concept represents a reusable idea across multiple sources and your own thinking.

An edge represents a particular relationship between objects.

The spec already makes an important distinction: derived book passages can be regenerated, but a passage that you touch becomes durable evidence. It also preserves multiple selectors for highlights, so re-parsing a book does not automatically orphan the material you saved.

Strengthening required: duplicate-import semantics
The latest document says that re-importing identical bytes creates nothing. But your earlier design preference was to keep imports separate by default and offer duplicate detection.

Retry of the same import operation: use its idempotency key to return the original result without creating another record.

This layer is close to a good foundation.

The design is aligned with three needs:

You can keep writing without asking where each thought belongs.

Every committed object becomes searchable and traceable.

The system can recover after interruptions without inventing a second copy of the same work.

What needs hardening
Be exact about when something is saved. A desktop outbox should distinguish “saved on this device” from “acknowledged by the cloud.” If the network is down, local work should remain durable and sync later. The interface must not imply that content is safely backed up remotely when it exists only on the device.

Do not assume a database transaction includes object storage. PostgreSQL cannot make a transaction atomic across itself and an external blob store. The staged-import approach in the spec is the right pattern: upload and verify the content, stage parsing results, and publish the source version only after the required parts are ready. Add compensating cleanup for abandoned uploads and a recovery path for partial imports.

Define draft and revision guarantees precisely. The current design uses mutable drafts and commits a revision after settling. That can work, but concurrent edits need clear rules: a stale base revision creates a sibling branch, and the application preserves both instead of quietly overwriting one. A last-write-wins draft policy must not erase committed text or silently discard meaningful concurrent edits.

Make deletion semantics explicit. A tombstone can hide an object while retaining history. A purge is different: it removes the object and its derived material, subject to stated backup-retention limits. The purge job must account for embeddings, decisions, candidate sets, edge evidence and blobs, not just the primary row.

Keyword and lexical indexing

9. Layer 7 — Concept induction: the system must be able to create genuinely new concepts
This layer is mandatory for your question about continuous compounding.

If Arivo can only match new material to existing concepts, its graph will eventually become a static vocabulary. To keep growing, it must identify potentially new concepts, distinguish them from existing ones, create provisional records and then refine them as new evidence arrives.

Your revised design already sketches the right stages. They need to become first-class in the architecture.

1. Detect candidate mentions

From highlights, notes, journal writing, touched passages and structural definition cues

2. Normalize and separate senses

Normalize spellings and aliases, but distinguish different meanings of the same term

3. Search existing concepts

Use alias, lexical, embedding and context candidates, then let Kev classify the matches

4. Create a provisional concept

When no existing concept fits and the evidence gate passes

5. Accumulate independent evidence

Add aliases and context; graduate, split, merge or retire automatically under versioned policies

How to make birth automatic without turning every phrase into a concept
The system should distinguish a mention from a concept. A phrase appearing once in a sentence is not automatically a durable concept. However, a new mathematical definition, a carefully highlighted idea or a recurring term in your notes may deserve a concept record before several books have corroborated it.

A good policy combines:

Attention: whether you deliberately highlighted, annotated, cited or discussed the phrase.

Structure: whether the source defines the term, lists it in a glossary, or introduces it formally.

Novelty: whether the phrase matches an existing concept or alias.

Sense coherence: whether uses of the phrase refer to the same meaning.

Distinctiveness: whether it is a useful concept rather than generic language.

Independent corroboration: whether different sources or contexts reinforce the interpretation.

A new concept can begin as provisional. It should have a stable ID, source-linked mentions, an extractive label, and a verbatim defining sentence with provenance where available. A future model can improve its clustering without replacing the original evidence.

The concept lifecycle must also define automatic alias addition, split detection, reversible equivalence links, and hard-merge promotion. For merges, retain original concept IDs and lineage; use reversible redirects rather than destructively reparenting or rewriting the underlying edges.

Do not let the graph manufacture its own evidence
An important safety property: a concept or edge must not become more credible merely because Arivo repeatedly traversed its own inferred connections.

Evidence derived from another inferred edge should not count as an independent source. Expansion needs provenance and a limit on inference depth, plus degree caps and hub penalties.

Your old spec blocks all inferred edges from candidate expansion.
